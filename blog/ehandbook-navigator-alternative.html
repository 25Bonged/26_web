ETAS EHANDBOOK-NAVIGATOR Alternatives (2026)

ETAS EHANDBOOK-NAVIGATOR is the de facto way to browse ECU function documentation — but its license-server model, cost, and cloud direction push many teams to look for an EHANDBOOK-NAVIGATOR alternative. This guide covers what to look for in a replacement and the options worth evaluating in 2026.

If you mainly need to open .ehb containers, navigate functions, and resolve labels to ECU parameters without being tied to a seat license, read on.

Why Teams Look for an EHANDBOOK Alternative

EHANDBOOK-NAVIGATOR is capable, but the friction is consistent across teams we talk to:

  • License-server dependency. Seats are gated by a server; offline or air-gapped engineers get blocked.
  • Cost and seat scarcity. Licenses are expensive and rationed, so the engineer who needs to check a label often can't.
  • Data-residency concerns. ECU documentation is sensitive OEM IP; teams increasingly want it to stay on-premise, not in a vendor cloud.
  • Limited extensibility. Hard to script, automate, or integrate into a modern toolchain.

A good alternative should remove the license server without losing the core navigation and A2L capabilities that make EHANDBOOK useful.

The Options

1. XHandbook Navigator (Vehicle Lab)

XHandbook Navigator is a local-first desktop equivalent of EHANDBOOK-NAVIGATOR built specifically to remove the license-server problem.

What it does:

  • Opens existing .ehb, .ehbcrypt, and .ehbp containers (ZIP of DITA docs, KAOM models, SQLite metadata, and a search index)
  • Document and Model Explorer with KAOM graph auto-layout, global search with container provenance, and label popups showing metadata plus 2D/3D curve and map visualizations
  • Deep A2L integration — convert A2L → container, resolve any label to its CHARACTERISTIC / MEASUREMENT / AXIS_PTS definition, ECU address, record layout, conversion and units, with reverse lookup
  • A standalone build-ehb tool to generate containers from A2L plus PDF/HEX inputs
  • No license server, runs on-prem so ECU documentation never leaves your environment; cross-platform (Windows / macOS / Linux)

It's validated against real Bosch/ETAS golden containers, so existing documentation opens as expected.

Best for: teams that want EHANDBOOK-style navigation and A2L depth without seat licenses or cloud dependency.

2. Internal Wikis / Document Portals

Some teams export documentation to a wiki or PDF portal. This removes license cost but loses everything that makes EHANDBOOK valuable — A2L-aware label resolution, KAOM model navigation, and live parameter context. Workable as a read-only archive; not a real navigator.

3. Staying on EHANDBOOK-NAVIGATOR

If you're deep in the ETAS ecosystem and license cost isn't a constraint, staying put is reasonable. The question is whether the license server and data-residency model fit where your organization is heading.
